# PC-01: aprender cinemática directa

## Ejecutar y reproducir

Desde la raíz de RELAX, con la biblioteca instalada en el entorno `relax`:

```powershell
python -m planar_arm.pc01 --output runs/pc01_seed42
python -m unittest discover -s tests -v
python -m planar_arm.pc01 --load runs/pc01_seed42/model.pt
```

El directorio de entrenamiento debe estar vacío. Para repetir una corrida usar
otro directorio, por ejemplo `--output runs/pc01_repeat`. Parámetros configurables:
`--samples 10000 --seed 42 --l1 1 --l2 1 --hidden 32 --epochs 60 --batch-size 128
--steps 30 --lr-x 0.1 --lr-p 0.001 --threads 1`. `--help` enumera las opciones.
`--load` utiliza la configuración del checkpoint e imprime métricas sin entrenar;
los argumentos de entrenamiento no se aplican en ese modo.

La corrida usa CPU, float32, semilla de Torch, generador propio para el orden de
DataLoader y algoritmos deterministas. El dataset conserva el generador anterior:
8000/1000/1000 con semilla 42, ángulos uniformes en `[-pi, pi)`, sin transformar las
unidades. Reproducibilidad numérica requiere las mismas versiones y entorno;
cambiar el tamaño del lote puede alterar tanto el entrenamiento como el redondeo.

## Arquitectura y mecanismo real de la biblioteca

La arquitectura sigue el tutorial incorporado
`third_party/PredictiveCoding/1_supervised_learning_pc.ipynb`:

```text
ángulos (2) → Linear(2,32) → PCLayer → tanh
            → Linear(32,32) → PCLayer → tanh → Linear(32,2) → posición
```

Tiene 1218 pesos y sesgos aprendidos. No hay activación final que restrinja las
coordenadas. Se conserva la representación en radianes para establecer una primera
referencia; la red no incorpora periodicidad ni las fórmulas del brazo.

En `PCLayer.forward` (`third_party/PredictiveCoding/predictive_coding/pc_layer.py`),
el modo `train()` devuelve un estado independiente `x`, en lugar de la predicción
`mu`. Inicialmente `x = mu.detach().clone()`. La capa almacena
`0.5 * sum((mu-x)^2)`. La energía total del experimento agrega los dos errores
ocultos y `0.5 * sum((output-target)^2)` como término supervisado. La pérdida recibe
solo las etiquetas del dataset, sin llamar a la cinemática analítica.

`PCTrainer.train_on_batch`, en `pc_trainer.py`, calcula esos términos y sus
gradientes mediante autograd. `get_model_parameters()` excluye los estados `x`
del optimizador de pesos. El adaptador local `make_trainer` configura:

1. Inicialización de latentes y reinicio del optimizador de estados en cada lote.
2. Iteraciones `0..T-2`: SGD sobre estados, entradas y etiquetas fijas, sin pasos
   del optimizador de pesos.
3. Iteración `T-1`: recalcula energía y gradientes y aplica un paso Adam solo a
   pesos y sesgos. Los estados ya no se actualizan en esta iteración.

Con `T=30` hay 29 actualizaciones de estados y una de pesos. No se exige convergencia
exacta. El tutorial y MNIST utilizan `update_p_at='last'`; aquí se evita además
actualizar estados en ese último paso para hacer explícita la separación.
La biblioteca puede calcular/acumular gradientes de pesos durante la relajación,
pero los borra antes del paso final: calcular gradientes no implica actualizar pesos.
Las fronteras `PCLayer` cortan la cadena directa con estados independientes; no se
entrena una MLP convencional mediante el error final propagado a través de toda
la red. Autograd calcula las derivadas de la energía PC. No se implementó una
dinámica propia ni se modificó el submódulo.

El precedente local `notebooks/mnist_bpc_generation.ipynb` también separa SGD de
estados y Adam de parámetros y descarta los latentes al guardar. PC-01 utiliza
solo el camino directo, sin conexiones bidireccionales ni optimización de ángulos.

## Evaluación y registros

En `eval()` las `PCLayer` son transparentes: se mide una pasada directa sin
relajación iterativa y sin acceder a etiquetas durante la predicción. Todas las
curvas de error cartesiano de entrenamiento/validación usan este modo. Su error
es distinto del error de salida de los estados relajados durante el entrenamiento.

Se registra época 0, luego cada época. El checkpoint se selecciona por menor RMSE
de validación, incluida la referencia inicial. El conjunto de prueba no participa
en actualizaciones ni selección: se evalúa después de restaurar el checkpoint
elegido. El comando de recarga puede repetir esa evaluación sin modificar el modelo.

Para cada muestra, `d = ||predicción-objetivo||₂`. Media, mediana y máximo corresponden
a `d`; **RMSE = sqrt(mean(d²))**, en unidades de longitud. No es el RMSE promediado
por las dos componentes, que sería menor por un factor sqrt(2).

Regiones fijadas antes de evaluar prueba:

- Frontera angular: al menos un ángulo a menos de 0.2 rad de ±pi; interior: resto.
- Tres intervalos radiales iguales entre `abs(L1-L2)` y `L1+L2`.
- Cuatro cuadrantes según la posición real.

Cada región incluye cantidad de muestras. Una región vacía produce métricas null.
Los errores se calculan contra etiquetas originales float64; las predicciones son
float32. No se proyectan predicciones sobre el espacio alcanzable.

Artefactos en el directorio de salida (ignorado por Git):

- `model.pt`: solo pesos/sesgos, arquitectura, configuración, época seleccionada y
  RMSE de validación. No contiene los estados por lote ni permite reanudar Adam.
- `config.json`, `environment.json`: parámetros, versiones, revisión Git del
  proyecto/submódulo, estado del repositorio y hashes de las fuentes Python.
- `dataset.npz`: particiones exactas, semilla, columnas y longitudes.
- `history.json`: errores directos por época y energías del último paso de cada
  lote, sumadas y divididas por cantidad de muestras. Estas energías se miden
  **antes** de la actualización de pesos de ese lote; no son energía global de
  la red al finalizar la época. La energía PC oculta excluye la pérdida de salida.
- `inference_trace.json`: energías oculta, de salida y total del primer lote,
  antes de cada actualización, por muestra. El aviso de lentitud de PCTrainer
  corresponde a registrar todas las iteraciones únicamente de ese lote.
- `metrics.json`, `test_predictions.npz`: métricas finales y predicciones de prueba.
- `training.png`, `inference_trace.png`, `predictions.png`: evolución, relajación
  del primer lote y comparación/error por regiones. Se usa Agg sin ventanas.

Para reutilizar en un experimento posterior:

```python
import torch
from planar_arm.pc01 import load_model

model, checkpoint = load_model("runs/pc01_seed42/model.pt")
with torch.no_grad():
    xy = model(torch.tensor([[0.5, 1.0]], dtype=torch.float32))
```

Esta carga deja el modelo en `eval()`. PC-02 requerirá decidir cómo fijar la
observación cartesiana y liberar ángulos/estados; esa inferencia no está incluida.

## Límites del experimento

Una semilla y una partición permiten una primera referencia, no una estimación de
variabilidad estadística. Las regiones cercanas al corte angular pueden tener
mayor error: el mapa físico es periódico pero la red recibe valores separados por
casi 2pi. Una representación seno/coseno es una mejora posterior posible. También
se pueden investigar más iteraciones, otras tasas y capacidad usando validación;
prueba debe reservarse para la evaluación final de cada protocolo definido.

El muestreo es uniforme en ángulos, no en área, y la salida no respeta por construcción
las restricciones geométricas. No hay garantías de generalización a longitudes
distintas, ruido, trayectorias o cinemática inversa. Aprender el mapa directo tampoco
resuelve la ambigüedad de las dos ramas de la inversa.

## Resultado de referencia ejecutado

Se ejecutó la configuración por defecto con el intérprete Conda `relax`, PyTorch
2.14.1+cpu, durante 60 épocas (aproximadamente 131 segundos de entrenamiento y
evaluación). El menor RMSE de validación fue 0.113237 en la época 59; ese checkpoint
se usó para prueba. El RMSE inicial de validación era 1.566913.

| Métrica de prueba (1000 muestras) | Valor |
| --- | ---: |
| Distancia media | 0.096306 |
| Distancia mediana | 0.087992 |
| RMSE euclídeo | 0.112826 |
| Distancia máxima | 0.450033 |

| Región | Muestras | RMSE |
| --- | ---: | ---: |
| Cerca del corte angular | 125 | 0.166804 |
| Interior angular | 875 | 0.102827 |
| Radio [0, 2/3) | 206 | 0.115073 |
| Radio [2/3, 4/3) | 253 | 0.119370 |
| Radio [4/3, 2] | 541 | 0.108738 |
| Cuadrante I | 244 | 0.091146 |
| Cuadrante II | 271 | 0.141529 |
| Cuadrante III | 243 | 0.128669 |
| Cuadrante IV | 242 | 0.071908 |

El error es mayor en la vecindad del corte angular. La dependencia por cuadrante
indica que la aproximación aprendida no conserva exactamente la simetría física.
Los errores por intervalo radial son más parecidos. Son observaciones de una
única corrida; no se ajustaron hiperparámetros después de observar prueba.

En el primer lote, la energía total por muestra bajó de 1.199316 a 0.910864 durante
la relajación. La energía oculta creció desde cero mientras bajaba el término de
salida, consistente con la transmisión del error hacia estados internos. Esto
no demuestra convergencia completa ni garantiza estabilidad con otras tasas.

Pasaron las 20 pruebas automáticas (15 anteriores y 5 nuevas). Las nuevas verifican
separación de actualizaciones de estados/pesos, actualización de la primera capa,
entradas fijas, reproducción de actualizaciones PC, transparencia de eval, guardado
y recarga, definición de métricas y partición de regiones. La recarga del checkpoint
de la corrida completa reprodujo las métricas finales. No se repitió una segunda
corrida completa de 60 épocas.
